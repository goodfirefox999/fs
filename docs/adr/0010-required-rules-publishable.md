# ADR-0010：publishable 基于事项必需规则集

- 状态：已采纳
- 日期：2026-11-01
- 决策者：评审要求（2026-11-01 第二轮，"第 3 条尤其别跳"）

## 背景

原 `publishable` 的逻辑是：只要有任何未考证规则命中 / 有争议 / 有冲突 → false。

后果：要产出第一个"可用"结论，必须把 34 条断言级规则全部考证完。
实际上会**永久 false**，P0 考证工作失去唯一的验收信号。

## 决策

1. 新增 `core-rule/config/required_rules.yaml`：`task_kind → 必需规则 id 列表`。
   选取标准：该事项的**否决层核心**（缺了就不能判断"这个日子能不能用"）。
2. `publishable` 改为：
   - **有必需集时**：`tier != REJECTED` 且 无冲突 且 **必需集内全部 `participation == "判定"`**
     （无"演示命中"、无"输入不足"）。
     非必需规则待考证只降级为**「参考层缺失」提示，不阻塞发布**。
   - **无必需集时**：退回严格口径（旧逻辑）。
3. 报告新增「必需规则集：共 N 条，已可判定 M 条」+ 未可判定项清单
   （把报告变成"还差什么才能发布"的操作指南）。

## 验收信号

修造的必需集共 10 条，当前已可判定 9 条（只差 `ASSERT-REPEAT-001`）。
**补齐这 1 条原文 → `publishable` 第一次为 true。**
这就是 P0 考证的完成定义。

## 后果

- ✅ 考证有了可量化的进度指标（"必需集 9/10 可判定"）。
- ✅ 非必需规则（如月五黄、都天煞）的缺口不再阻塞主链路。
- ⚠️ 必需集选取本身是**人的判断**（哪些规则算"否决层核心"）。
  当前按评审给的 P0 六条 + 结构类断言选取，已登记在 `QUESTIONS.md` Q-011 待确认。
- ⚠️ 若必需集配得过窄，会出现"发布了一个没查关键项的结论"。
  CI 已校验必需集引用的规则必须存在；但"选得对不对"只能靠人。

## 与 ADR-0009 的联动

拆分出的 8 条 `ASSERT-*` 里，`ASSERT-ZIXING-001`、`ASSERT-REPEAT-001` 被列入修造必需集 ——
因为它们对应"结构性问题是否影响用事"这一核心判断，缺了就不能说"这个日子能用"。
其余 6 条（六害/相破/三刑等）暂列为非必需（参考层），可后续按需加入。

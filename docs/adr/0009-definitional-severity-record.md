# ADR-0009：定义级不得携带吉凶 severity（Q-010 闭环）

- 状态：已采纳（**推翻 ADR-0007 的 severity 设计**）
- 日期：2026-11-01
- 决策者：评审裁定（2026-11-01 第二轮）
- 触发：评审指出 `DEF-REPEAT-001` 携带 `severity=慎用` 并计入 `strong_avoid`，
  "这已经不是定义，而是用定义级的确定性外衣包装断言级的结论"。

## 背景

ADR-0007 引入 `status: 定义级`，但只挡住了 `hard_veto` 与 `severity=禁用`，
**没挡住 `慎用`**。结果 `DEF-REPEAT-001` 做了三件事：

1. 声明"三见是结构事实"（定义级，正确）
2. 携带 `severity=慎用`（断言，错误）
3. 计入 `strong_avoid` 影响 tier（把断言后果制度化，错误）

用户看到「结构判定（定义级，已确定）｜三见 慎用」时，会理解为"这是确定的凶"。
**这正是评审警告的"断言伪装成定义"。**

## 决策

1. 新增 severity 值 **`记录`**，为定义级**唯一**允许的严重度。
2. 定义级规则**不进** `vetoes / cautions / positives`，**不影响 state 与 tier**。
3. 每条定义级规则的"吉凶主张"部分拆为独立断言规则（`ASSERT-*`），`status: 待考证`。
4. 加载期三条硬校验：
   - `status=定义级` → `severity` 必须 == `记录`；
   - `severity=记录` → `status` 必须 == `定义级`；
   - 定义级不得用 `severity_overrides` 引入吉凶值。
5. CI 兜底：`rules lint` 再查一遍（防绕过 loader 的路径）。

## 一句话原则（写进 DEVELOPMENT.md 与 AGENTS.md）

> **定义级只回答"是什么关系、几次、在哪个方位"，不回答"好不好"。**
> 吉凶判断一律归断言级，一律待考证。

## 后果

- ✅ 报告不再出现「定义级，已确定｜慎用」这种混合语义。
- ✅ tier 被拉低的唯一来源是**诚实的 unknown 断言**，不是伪装成定义的评价。
- ✅ 金标准案例：三未重复 → `DEF-REPEAT-001` 记录（确定）+ `ASSERT-REPEAT-001` unknown（待考证）。
- ⚠️ 规则数增加 8 条，`publishable` 的必需集需同步更新（见 ADR-0010）。
- ⚠️ 若人类考证者认为某条"定义级"其实含吉凶主张，应退回 `待考证`（状态机允许）。

## 教训（写给未来的 Agent）

ADR-0007 只挡住了"最极端"的 `禁用`，就以为防住了断言伪装。
**防线要按语义维度穷举，不是按"最严重的那个值"堵。**
severity 是一个完整维度（禁用/慎用/可用/推荐），只堵住一头等于没堵。

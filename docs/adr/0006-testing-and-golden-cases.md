# ADR-0006：测试策略与金标准案例

- 状态：已采纳
- 日期：2026-11-01
- 决策者：实现者（Agent），待人类复核

## 背景

择日系统的测试有两个特殊困难：

1. **无法用"准确率"衡量**（不承诺灵验），只能验证"实现是否符合宣称规则"。
2. **规则本身待考证**，若测试依赖规则正确性，会陷入循环论证。

## 决策

分四层，各层验证不同命题：

| 层 | 验证的命题 | 手段 |
|---|---|---|
| 历法层 | "四柱/节气算得对" | 与权威历书对照（±2 min）+ 属性测试不变量 |
| DSL 层 | "规则被正确解析与求值" | 算子全覆盖 + 三值逻辑真值表 + 84 条规则级向量 |
| 引擎层 | "三态/分层/冲突按定义工作" | 构造性测试（人为注入命中） |
| 案例层 | "整链路输出符合宣称" | 金标准案例 GS-2027-0711 + 契约测试 |

**关键设计：规则级测试向量与规则解耦。**

`tests/cases/rule_tests/*.yaml` 只声明"给定 ctx 的差异，期望 hit/miss/unknown"，
不依赖规则是否符合古籍。这样即使规则内容被考证者改写，向量仍能验证求值器是否正确。

**金标准案例 GS-2027-0711** 同时检验五件事：

1. 四柱 = 丁未 丁未 辛卯 乙未（历法正确）
2. 亥卯未三合扶山被识别为正向证据（结构检测正确）
3. 三未重复 ≠ 未未自刑（术语纠正生效）
4. 阴府降级为 unknown 而非静默通过（未知暴露机制生效）
5. tier 不为 PREFERRED（分层向量生效）

## 理由

- 把"规则对不对"与"实现对不对"分开验证，才能让 Agent 在没有考证权的情况下推进工程。
- 金标准案例是唯一能同时覆盖五层链路的测试，必须阻断合并（`tests/golden`）。
- 打乱对照实验（`case_runner`）用于检测"规则集对案例无判别信息"这一隐性失败模式。

## 后果

- ✅ 438 个测试，覆盖率 83%，金标准全绿。
- ⚠️ 案例库仅 1 条 A 级案例，统计意义有限；`case_runner` 的打乱对照在 n<4 时不启用。
- ⚠️ `core-eval/sensitivity.py` 与 `app-zeri` 部分错误分支未覆盖（见 Q-008）。

## 未采纳的备选

| 方案 | 否决理由 |
|---|---|
| 用作者判定做"准确率"指标 | 违反合规红线，且样本极小无统计意义 |
| 只做单元测试不做案例 | 无法发现跨层集成缺陷（如事实键名冲突） |
| 用真实择日结果做回归 | 无法验证（无客观真值），且涉及"灵验"假设 |

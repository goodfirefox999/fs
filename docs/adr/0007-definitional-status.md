# ADR-0007：定义级规则分层——区分"算术推论"与"吉凶断言"

- 状态：已采纳
- 日期：2026-11-01
- 决策者：评审意见（2026-11-01）+ 实现者
- 触发：评审指出「42 条全待考证 → 系统永远不给可用结论」的代价被高估，
  因为把两类性质完全不同的规则塞进了同一个状态机。

## 背景

原状态机只有 `draft / 待考证 / 已考证 / 有争议 / 弃用`，其中 `已考证` 强制要求
`citation.quote` + `verified_by`（古籍原文 + 人类签名）。这条约束挡住了编造出处，是对的。

但它把两类东西混为一谈：

| 类型 | 例子 | 需要什么出处 |
|---|---|---|
| **定义级**（算术推论） | 六冲表、三合局、自刑四组、地支重复计数、方位角→二十四山 | 内核规格条款 |
| **断言级**（吉凶主张） | 三煞占山、阴府、天德、扶山补龙 | 古籍原文 + 考证签名 |

结果是：`未未不是自刑` 这个**已经确定正确**的结构结论，在报告里和"阴府是否成煞"一样标 `unknown`，
用户无法区分"我们不知道"和"这在定义上如此"。

## 决策

新增状态 `定义级`，与 `已考证` **正交**：

```
draft ──→ 待考证 ──→ 已考证
  │         │  ↑
  └──→ 定义级 ┘  └── 定义级可退回待考证（若发现它其实含吉凶断言）
```

**加载期三条硬约束**（防止把吉凶断言伪装成定义级）：

1. `citation.kind` 必须为 `spec`（不是 `classic`）；
2. `citation.quote` 必须写明规格条款原文（如"自刑四组：辰辰、午午、酉酉、亥亥"）；
3. `hard_veto` 必须为 `false`，`severity` 不得为 `禁用` —— **否决是吉凶断言**。

**权限**：Agent 可创建 `定义级`（它是"是否只是算术推论"的技术判断），
但必须填 spec 出处；`已考证` 仍只能由人类签名。

**引擎行为**：

- 定义级规则**直接参与判定**，结论进 `Evaluation.structural`（不分派别，按 rule_id 去重）；
- `severity=慎用` 的定义级结构计入 `strong_avoid_count`（影响 tier）；
  `severity=可用` 的中性结构（如三合局成立）仅展示，不影响 tier；
- 定义级**不进** `positives`（结构事实不是"吉"）；
- 定义级规则求值为 `unknown` 时仍进 `unknowns`（reason=missing_input），但不会与结构结论混淆。

## 后果

- ✅ 系统第一次产出**确定的**结构结论（"该日课有三未重复，确定成立"），而非全部 `unknown`。
- ✅ 报告分「结构判定（定义级，已确定）」与「吉凶判定」两节，用户能区分两类不确定性。
- ✅ `tier` 仍锁在 `NEEDS_REVIEW`（因为断言级全待考证），"不发布"的合规约束没有被削弱。
- ⚠️ 定义级结构的"慎用"严重度是**评审裁定**（2026-11-01：结构性冲突按 MEDIUM_AVOID 处理），
  不是古籍原文；已在每条规则的 `notes` 中标注。
- ⚠️ 若人类考证者认为某条"定义级"其实含吉凶主张，应退回 `待考证`（状态机允许）。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 直接放宽 `已考证` 的引文要求 | 会让编造出处通过 CI，破坏核心约束 |
| 把所有结构规则改成 `已考证` 并填 spec 出处 | 混淆两种出处性质，报告无法区分 |
| 不做分层，靠报告文案说明 | 状态机层面没有约束，Agent 迟早会把断言混进定义级 |

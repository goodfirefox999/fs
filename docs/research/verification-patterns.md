# 验证模式：找一条"必然成立"的恒等式，然后全时段扫

> 起因：二十八宿值日那条 `宿七政 = 当日星期`，比 29 项单测更有杠杆 ——
> 它不依赖"恰好算出某个期望值"，而依赖一个跨 200 年成立的恒等式。
> 本文把这种模式固化成模板，供后续每个新模块套用。
>
> **判据：没有恒等式的模块，只能算"写完了"，不能算"验证过"。**

## 一、模式（四步）

```
1. 命题：写出一条 P(data) 恒为真的等式，且它**不引用**被测算法自身的中间量
2. 独立量：等式另一侧必须来自**另一个体系**（星期、六十甲子、洛书九宫、天文几何）
3. 扫描：在可计算的最大区间逐日/逐例求值，统计违例数（必须为 0）
4. 反证：人为把实现扰动一位/一格，断言违例数显著 > 0 —— 否则这条恒等式是恒真的废话
```

第 4 步是分水岭。没有第 4 步，恒等式只是"看起来对"；有了第 4 步，它才具备**否证能力**。

## 二、已落地的恒等式（可抄）

| 模块 | 恒等式 | 独立量来源 | 扫描面 | 反证方式 |
|---|---|---|---|---|
| 二十八宿值日 | `宿之七政 == 当日星期` | 七曜—星期对应（跨文明固定） | 1900-2100，73,414 天，**0 违例** | 宿序 +1 或锚点移 1 日 → 违例率 ≈ 6/7 |
| 建除十二神 | `建日 ⟺ 日支 == 月支`；`破日 ⟺ 日支冲月支` | 六冲表（独立起例） | 全月支×日支 144 组 | 位次公式 ±1 → 破日与月破错位 |
| 十二黄黑道 | 青龙起例后顺行 12，`值神` 与日支之差恒定 | 青龙起例表（另一起例） | 12 月支 × 12 日支 | 顺行改逆行 → 勾陈等 6 星错位 |
| 紫白九宫 | `五黄宫 == 入中星顺飞第 4 位`；`反查星→宫` 与 `宫→星` 互逆 | 洛书路径（独立序列） | 入中星 1–9 全枚举 | 飞布方向翻转 → 五黄宫变镜像 |
| 年紫白 | 逐年逆退一位：`star(Y+1) == wrap9(star(Y) - 1)` | 六十甲子年序 | 1864–2100 | 改顺退 → 2024 不再是三碧 |
| 日柱 | `日柱序 == (JD - JD0) mod 60` | 儒略日（连续计数） | 1900–2100 | 中间插一个闰日 → 全段错位 |
| 旬空 | `旬首 + 10 位 == 空亡两支前一位` | 六十甲子旬结构 | 6 旬 × 10 日 | 空亡表错一位 → 旬首日本身落空 |
| 纳音 | 六十甲子纳音成 30 对，`i` 与 `i+30` 同纳音 | 五行循环 | 60 项 | 表错位 → 成对关系破裂 |
| 天德/月德 | 月德只取阳干：`{丙,甲,壬,庚}`，永不出现乙丁辛癸戊 | 阴阳干定义 | 12 月支 | 混入阴干 → 立刻违反 |

## 三、没有恒等式的模块（只能等原典，不许自称验证）

| 模块 | 为什么没有 | 现状 |
|---|---|---|
| 日紫白起元 | 「符头法」与「连续 60 日法」都是**约定**，没有第三方量能判定谁对 | `GAP-ZIBAI-DAYYUAN`；规则 `engine_eligible=false` |
| 值宿吉凶 | 「角吉亢凶」是断言，没有可计算的恒等式 | 只作参考层（`coarse_label_no_primary_source`） |
| 天德卦位取支 | 渊海/考原两说在卦宫层等价，取单支是**约定** | 口径 `tiande_guaxiang` 回显，整宫为默认 |
| 斗首贪狼/廉贞吉凶 | 五化曜吉凶各本不一 | 参考层，默认不入路由 |
| 玄空大卦卦运 | 卦运起法无原典 | 等原典 |

**这条边界要写进评审口径**：模块"跑通 + 单测绿"只证明自洽；只有当它能被一条独立恒等式否证时，
才配得上"验证过"三个字。

## 四、给新模块的检查清单

新增任何计算层，PR 里必须回答：

1. **恒等式是什么？** 写不出来 → 归入第三节，标 `engine_eligible=false` + 理由，不许进结论强度。
2. **另一侧来自哪个体系？** 若与被测算法同源（例如用同一张表反查自己），不算独立。
3. **扫了多大面？** 必须给出"区间 + 样本数 + 违例数"，不接受"抽样通过"。
4. **扰动后会不会响？** 给出一个定点变异（`make mutation` 或临时改一位），断言违例数上升。
5. **恒等式本身有没有被测试锚定？** 测试名写进本文表格，改名/删除时本文失效可被发现。

## 五、与现有门禁的关系

| 门禁 | 抓什么 | 抓不到什么 |
|---|---|---|
| 单元测试 | 已知输入的已知输出 | 表整体错位（期望值也一起写错） |
| 变异测试 | 实现改动是否被测试发现 | 未被任何测试覆盖的模块（变异点不存在） |
| **恒等式扫描** | **表错位、锚点漂移、跨体系不一致** | 约定本身对不对（那是考证问题） |
| 死代码门禁 | 模块写了没接上 | 接上了但算错 |

四者互补，缺一条就有一类故障永远抓不到 —— 2026-11-02 的 `zibai` 事故正是"死代码门禁"缺位。

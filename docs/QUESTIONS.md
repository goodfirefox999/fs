## Q-001 🔴 42 条规则全部缺原文与卷次

**现状**：`core-rule/rules/**` 共 42 条规则，`status` 全为 `待考证`，`citation.quote` 全为 `null`。

**为什么 Agent 不能代劳**：填 `quote` 需要核对古籍原文，属于考证行为。若 Agent 自行填写，
即为编造出处（AGENTS.md 硬禁止第 1 条）。

**需要人类提供**（每条规则一行即可）：

| 字段 | 说明 |
|---|---|
| `citation.source` | 书名（已填，如《协纪辨方书》） |
| `citation.edition` | 版本（如"四库全书本"） |
| `citation.juan` | 卷次（如"卷三十六"） |
| `citation.quote` | 原文（可直接引用的完整句） |
| `citation.verified_by` | 考证者姓名 |
| `status` | 改为 `已考证`（需 commit trailer `Verified-B by:`） |

**影响**：在补齐之前，系统默认不产生任何"可用"结论 —— 所有命中只登记为 `unknown`，
`tier` 至少 `NEEDS_REVIEW`。这是刻意设计（见 ADR-0005）。

## Q-003 🔴 「未时天德 vs 勾陈」的具体起例缺失

**背景**：金标准案例（GS-2027-0711）要求"未时流派分歧必须输出 CONFLICT"。

**当前实现**：`state_divergence` 机制已实现并生效（`public=存疑` vs `zhengwuxing=可用`），
但**具体的"天德吉时 / 勾陈凶时"两条规则无法落地** —— 因为：

- 天德的起例（月支 → 天干/地支）存在多种版本；

**需要人类提供**：两派的起例表 + 原文。补齐后可按 `DS-*` / `XK-*` 派别落地，

**当前处置**：不伪造规则。金标准测试断言"未时相关规则命中时不得判 PREFERRED，
且必须出现至少一个 unknown 或 conflict"，已通过。

## Q-010 「定义级」的边界由谁裁定？（v0.3 已闭环）

> **裁定结果（2026-11-01 第二轮评审）**：
> 「`DEF-REPEAT-001` 必须拆，不能整体算定义级。『三未 = 同一地支出现三次』是定义级；
> 『三见即忌（慎用）』是断言。」
>
> **已执行**（ADR-0009）：
> - 新增 severity `记录`，为定义级**唯一**允许值；定义级不进 vetoes/cautions/positives，不影响 tier
> - 8 条 `DEF-*` 的吉凶部分拆为 `ASSERT-*`（待考证）
> - 加载期 + CI 双重白名单校验
> - 一句话原则写入 DEVELOPMENT 与 AGENTS：
>   **定义级只回答"是什么关系、几次、在哪个方位"，不回答"好不好"**
>
> 剩余待确认：`DEF-SANHE-001`（三合局成立）标 `记录` 是否合适 —— 已按"中性结构"处理。

**背景**：ADR-0007 引入 `status: 定义级`，用于"干支算术推论"（六冲表、自刑四组、重复计数等）。
Agent 可创建定义级规则，但需要 `citation.kind: spec` + 规格条款原文。

**风险**：Agent 可能把"某条吉凶主张"错误地判为"算术推论"，从而绕过古籍考证。

**已设防线**：

1. 加载期强制 `citation.kind=spec` + 非空 `quote`；
2. 定义级规则**不得** `hard_veto=true`、**不得** `severity=禁用`（否决必属断言）；
3. 定义级规则不进 `positives`（结构事实不算"吉"）；
4. 10 条迁移规则逐条在 `notes` 里写明"严重度依据评审裁定，非古籍原文"。

**需要人类确认**：

- 这 10 条的边界划分是否同意？（尤其 `DEF-REPEAT-001 地支三见` 的"慎用"严重度是评审裁定，
  不是古籍原文；若认为"三见即忌"本身是断言，应退回 `待考证`）
- `DEF-SANHE-001`（三合局成立）标"可用（中性）"是否合适？还是应该完全不设严重度？
- 后续新增定义级规则，是否要求"每次都要人类复核一次"（而非 Agent 自行判定）？

## Q-012 🔴 太岁坐向口径：建模方向疑与原典相反（ADR-0013 同轮降级，2026-11-01 新增）

**背景**：ADR-0013 预检核到《协纪辨方书·利用一·制煞要法》引《选择宗镜》：
「太歲可坐不可向，三煞可向不可坐，不易之論也」，与 `PUB-TAISUI-001`
（坐山山家 = 太岁年支 → 禁用）方向相反。评审另供两处按语（B 级，待逐字复核）：
「太岁，君也，坐之吉，向之凶，冲破坐山故也」；
「至可坐不可向，则不易之论。盖向太岁则坐于岁破矣，虽有吉星不能解也」。

**已执行（ADR-0013 D2，最低限度处置）**：`PUB-TAISUI-001` 移出必需集、
`hard_veto→false`、`severity→慎用`（过渡登记）、`status→有争议`。
**这不是终局**：慎用仍是对"坐太岁"的负面登记，而原文说"坐之吉"——
拆除硬否决优先于给"坐太岁"找正确登记位。

### 证据升级与内部一致性核对（2026-11-01 第六轮预检）

级别约定：**A** = 识典/维基在线页直接抓取、逐字核到；**A-** = 维基全览页检索逐字返回、未开页；
**B** = 二手转述。所有 A/A- 仍须四库影印对照 + 人类签名后方可录为正式 quote。

| # | 引文（预检） | 级别 | 位置 | 对 Q-012 的作用 |
|---|---|---|---|---|
| P1 | 「坐三煞，向太歲，此不能制者也，不可犯也。」 | A | 利用·制煞要法 | 向太岁=不可犯（硬禁方向） |
| P2 | 「三煞在方在向……此可制而不易制者也，不可輕也。」 | A | 同上 | 三煞侧，佐证 003 降级 |
| P3 | 「太歲可坐不可向，三煞可向不可坐，不易之論也。」 | A | 同上 | H1 核心句 |
| P4 | 「太歲，君也，坐之吉，向之凶，衝破坐山故也。四柱八字合之吉，衝之尅之凶，以臣犯君故也。」 | A | 利用·太岁歲破 | 坐/向吉凶机制 |
| P5 | 「至可坐不可向，則不易之論。蓋向太歲則坐于歲破矣，雖有吉星，不能解也。」 | A | 同上（按语） | **SUIPO-001 同源支撑**：坐岁破=向太岁 |
| P6 | 「疊紫白三奇、禄馬貴人等吉星，則極吉……疊戊己、年尅、陰府、大煞等凶星，則又極凶……故太歲或在山，或在方，審其疊吉而不疊凶，則以四柱合之」 | A-（断句待影印复核，故不标 A） | 同上 | H1 的**条件项**：坐太岁吉是有条件的（叠吉不叠凶） |
| P7 | 「太岁到方而带戊己、打头火、金神也，月家则大月建、小儿煞也，此皆必不可犯者也」 | A- | 利用·论修方 | 方域条件（未来修方规则用）。**待确认**：「到方」是否涵盖坐山——若涵盖，P7 构成 H2 的有条件支撑（见预检结论） |

注：戊己/戊巳 两处写法有差异，影印复核时一并定字；P6 叠凶清单（戊己/年克/阴府/大煞）
与现有规则库存重叠——阴府已建模（PUB-YINFU-001），大煞未建模（Q-004）。

**一致性检查（结论：无互斥）**：
- C1 ✅ P3（太岁可坐）与 SUIPO-001 硬否决不矛盾：P5 坐岁破=向太岁 → 岁破忌的实质是"向太岁"。
- C2 ✅ P1 坐三煞不可犯 ↔ SANSHA-001/002 硬否决。
- C3 ✅ P2/P3 三煞可向 ↔ 003 降级。
- C4 ⚠️ P6 表明"坐之吉"非无条件——H1 裁定必须写成 **H1+条件**，不得记为"坐太岁无禁忌"。
  DSL 核查（2026-11-01）：组合条件 all/any/not 已支持（`dsl.py` COMBINATORS，深度≤4），
  条件形式今天就能写；但叠凶复合 fact 不存在（`facts.taisui.die_xiong` 需新建），
  其输入大煞（Q-004）、年克均未建模、阴府待口径（Q-005）——**条件性 TAISUI-001 有前置工程项**。
- C5 ⚠️ P7 属修方域，与坐山域 TAISUI-001 不直接相干，登记为未来修方规则的条件。

## Q-001 🔴 42 条规则全部缺原文与卷次

**现状**：`core-rule/rules/**` 共 42 条规则，`status` 全为 `待考证`，`citation.quote` 全为 `null`。

**为什么 Agent 不能代劳**：填 `quote` 需要核对古籍原文，属于考证行为。若 Agent 自行填写，

**需要人类提供**（每条规则一行即可）：

| 字段 | 说明 |

**影响**：在补齐之前，系统默认不产生任何"可用"结论 —— 所有命中只登记为 `unknown`，

## Q-010 「定义级」的边界由谁裁定？（v0.3 已闭环）

> **裁定结果（2026-11-01 第二轮评审）**：
> 「`DEF-REPEAT-001` 必须拆，不能整体算定义级。『三未 = 同一地支出现三次』是定义级；
> 『三见即忌（慎用）』是断言。」
>
> **已执行**（ADR-0009）：
> - 新增 severity `记录`，为定义级**唯一**允许值；定义级不进 vetoes/cautions/positives，不影响 tier
> - 8 条 `DEF-*` 的吉凶部分拆为 `ASSERT-*`（待考证）
> - 加载期 + CI 双重白名单校验
> - 一句话原则写入 DEVELOPMENT 与 AGENTS：
>   **定义级只回答"是什么关系、几次、在哪个方位"，不回答"好不好"**
>
> 剩余待确认：`DEF-SANHE-001`（三合局成立）标 `记录` 是否合适 —— 已按"中性结构"处理。

**背景**：ADR-0007 引入 `status: 定义级`，用于"干支算术推论"（六冲表、自刑四组、重复计数等）。
Agent 可创建定义级规则，但需要 `citation.kind: spec` + 规格条款原文。

**风险**：Agent 可能把"某条吉凶主张"错误地判为"算术推论"，从而绕过古籍考证。

**已设防线**：

1. 加载期强制 `citation.kind=spec` + 非空 `quote`；
2. 定义级规则**不得** `hard_veto=true`、**不得** `severity=禁用`（否决必属断言）；
3. 定义级规则不进 `positives`（结构事实不算"吉"）；
4. 10 条迁移规则逐条在 `notes` 里写明"严重度依据评审裁定，非古籍原文"。

**需要人类确认**：

- 这 10 条的边界划分是否同意？（尤其 `DEF-REPEAT-001 地支三见` 的"慎用"严重度是评审裁定，
  不是古籍原文；若认为"三见即忌"本身是断言，应退回 `待考证`）
- `DEF-SANHE-001`（三合局成立）标"可用（中性）"是否合适？还是应该完全不设严重度？
- 后续新增定义级规则，是否要求"每次都要人类复核一次"（而非 Agent 自行判定）？

## Q-012 🔴 太岁坐向口径：建模方向疑与原典相反（ADR-0013 同轮降级，2026-11-01 新增）

**背景**：ADR-0013 预检核到《协纪辨方书·利用一·制煞要法》引《选择宗镜》：
「太歲可坐不可向，三煞可向不可坐，不易之論也」，与 `PUB-TAISUI-001`
（坐山山家 = 太岁年支 → 禁用）方向相反。评审另供两处按语（B 级，待逐字复核）：
「太岁，君也，坐之吉，向之凶，冲破坐山故也」；
「至可坐不可向，则不易之论。盖向太岁则坐于岁破矣，虽有吉星不能解也」。

**已执行（ADR-0013 D2，最低限度处置）**：`PUB-TAISUI-001` 移出必需集、
`hard_veto→false`、`severity→慎用`（过渡登记）、`status→有争议`。
**这不是终局**：慎用仍是对"坐太岁"的负面登记，而原文说"坐之吉"——
拆除硬否决优先于给"坐太岁"找正确登记位。

### 证据升级与内部一致性核对（2026-11-01 第六轮预检）

级别约定：**A** = 识典/维基在线页直接抓取、逐字核到；**A-** = 维基全览页检索逐字返回、未开页；
**B** = 二手转述。所有 A/A- 仍须四库影印对照 + 人类签名后方可录为正式 quote。

| # | 引文（预检） | 级别 | 位置 | 对 Q-012 的作用 |
|---|---|---|---|---|
| P1 | 「坐三煞，向太歲，此不能制者也，不可犯也。」 | A | 利用·制煞要法 | 向太岁=不可犯（硬禁方向） |
| P2 | 「三煞在方在向……此可制而不易制者也，不可輕也。」 | A | 同上 | 三煞侧，佐证 003 降级 |
| P3 | 「太歲可坐不可向，三煞可向不可坐，不易之論也。」 | A | 同上 | H1 核心句 |
| P4 | 「太歲，君也，坐之吉，向之凶，衝破坐山故也。四柱八字合之吉，衝之尅之凶，以臣犯君故也。」 | A | 利用·太岁歲破 | 坐/向吉凶机制 |
| P5 | 「至可坐不可向，則不易之論。蓋向太歲則坐于歲破矣，雖有吉星，不能解也。」 | A | 同上（按语） | **SUIPO-001 同源支撑**：坐岁破=向太岁 |
| P6 | 「疊紫白三奇、禄馬貴人等吉星，則極吉……疊戊己、年尅、陰府、大煞等凶星，則又極凶……故太歲或在山，或在方，審其疊吉而不疊凶，則以四柱合之」 | A-（断句待影印复核，故不标 A） | 同上 | H1 的**条件项**：坐太岁吉是有条件的（叠吉不叠凶） |
| P7 | 「太岁到方而带戊己、打头火、金神也，月家则大月建、小儿煞也，此皆必不可犯者也」 | A- | 利用·论修方 | 方域条件（未来修方规则用）。**待确认**：「到方」是否涵盖坐山——若涵盖，P7 构成 H2 的有条件支撑（见预检结论） |

注：戊己/戊巳 两处写法有差异，影印复核时一并定字；P6 叠凶清单（戊己/年克/阴府/大煞）
与现有规则库存重叠——阴府已建模（PUB-YINFU-001），大煞未建模（Q-004）。

**一致性检查（结论：无互斥）**：
- C1 ✅ P3（太岁可坐）与 SUIPO-001 硬否决不矛盾：P5 坐岁破=向太岁 → 岁破忌的实质是"向太岁"。

- C3 ✅ P2/P3 三煞可向 ↔ 003 降级。
- C4 ⚠️ P6 表明"坐之吉"非无条件——H1 裁定必须写成 **H1+条件**，不得记为"坐太岁无禁忌"。
  DSL 核查（2026-11-01）：组合条件 all/any/not 已支持（`dsl.py` COMBINATORS，深度≤4），
  条件形式今天就能写；但叠凶复合 fact 不存在（`facts.taisui.die_xiong` 需新建），
  其输入大煞（Q-004）、年克均未建模、阴府待口径（Q-005）——**条件性 TAISUI-001 有前置工程项**。
- C5 ⚠️ P7 属修方域，与坐山域 TAISUI-001 不直接相干，登记为未来修方规则的条件。

**预检结论**：H1（含条件）已获 A 级直接支撑（P3+P4+P5+P6）；H2 **无直接文本支撑**
（4 组关键词检索无正证）——但保留一项待确认：P7 的「到方」若经影印术语确认涵盖坐山，
则 H2 升格为「有条件支撑」，裁定需重新权衡。"无支撑"与"可能有条件支撑"是两种强度的结论，不得混写。
Q-012 事实层面已可裁定，待人类完成：四库影印对照 → 勾选假设 → 联动表逐项打勾 → 签名。

## Q-024 条件性 verdict_type：规则命中方向随事实值变化时如何表达？（2026-11-03 新增）

**背景**：`verdict_type` 目前是单值枚举（`gate` / `vote` / `reference` / `None`），
假设「一条规则的性质是固定的」。但有一类规则**命中方向随事实值变化**：

| 规则 | 声明 severity | 正文 | 问题 |
|---|---|---|---|
| `DG-JIANCHU-001`（建除十二神） | 可用 | 「命中破/闭（一般不利）」 | 命中"建/成/开"是正向，命中"破/闭"是负向，同一条规则两个方向 |

`vote` 与 `reference` 都不对：标 `vote` 会把"建"日也当成正向票，标 `reference`
又会丢掉"破日确实不利"这个判定。这不是标注没想好，是**枚举表达不了条件性判定**。

**为什么 Agent 不能代劳**：加字段＝改 schema，会影响 `effective_verdict_type` 的返回值、
共识计票的分母（ADR-0015 的整数比）、以及报告"未归类"节的统计口径。三处都是
行为分布变更，须人类定方案后再动代码。

**候选方案**（择一，或另提）：

| 方案 | 形态 | 优点 | 代价 |
|---|---|---|---|
| A. 新增类型 | `verdict_type: conditional` + `direction_rule: {破: negative, 闭: negative, 其他: neutral}` | 语义直白，一条规则仍是一条 | 要定义 `direction_rule` 的 DSL 子集与求值时机 |
| B. 命中映射表 | `verdict_type_when_hit: {hit: vote, direction: {破: negative, 闭: negative}}` | 不改类型枚举，只加可选字段 | 与 `severity` 语义重叠，易产生"两处都能定方向"的歧义 |
| C. 拆规则 | 把 `DG-JIANCHU-001` 拆成 `DG-JIANCHU-JI-001`（建/成/开）与 `DG-JIANCHU-XIONG-001`（破/闭） | 零 schema 变更，现有类型直接可用 | 规则数 +1，`rules_manifest` 与 RT 向量要同步；且"一条起例拆成两条"会削弱"这是一条神煞"的语义 |

**方案 B 的硬前置（2026-11-03 评审追加）**：

方案 B 与 `severity` 语义重叠，不能只写"重叠"就进入裁定。**若选 B，必须同时定义**：

1. **优先级**：命中时方向以 `severity` 为准，还是以 `verdict_type_when_hit.direction` 为准？
2. **冲突处置**：两者矛盾时是加载期拒绝（fail-fast）、运行期取更严、还是取映射表并告警？
3. **单一真相源**：是否允许同一条规则同时写 `severity` 与 `verdict_type_when_hit`？
   若允许，报告必须回显"生效方向来自哪个字段"。

**未定义上述三项，方案 B 不可选**——否则会出现两个真相源，且报告无法解释为何
同一条规则在两处给出相反方向。

**合并议题：C 桶「定义级 10 条」的类型学（2026-11-03 评审追加）**：

C 桶不落标的理由不是"方向随命中变"，而是**定义级规则根本不是吉凶表态**：
它回答"是什么关系/几次/在哪个方位"（ADR-0007），既不是 `gate` 也不是 `vote`。
当前三值枚举（`gate` / `vote` / `reference`）没有它的位置：

- 标 `reference` → 把"唯一确定的结构事实"降级成"只展示不判定"，低估确定性；
- 标 `vote` / `gate` → 把定义事实伪装成吉凶表态，违反 ADR-0007 / ADR-0009；
- 新增第四种 `definition` / `structural` → 要定义它是否进 `structural` 桶、
  是否计入 `unlabeled_count`、是否影响 `publishable`。

这个问题与条件性 `verdict_type` 同属"单值枚举表达不了语义"，
**并入 Q-024 一并裁定**：定义级规则
（a）走 `verdict_type` 枚举并新增第四种类型，还是
（b）根本不进规则层、走"事实层"（则需说明现有 `DEF-*` 规则如何迁移）？

**影响面**：`DG-JIANCHU-001` 及后续同类（凡"同一神煞不同值不同吉凶"的规则），
外加 C 桶 10 条定义级规则（`DEF-*`）的类型学。按当前 63 条未标注规则粗查，
疑似条件性同类还有建除类的其余分支、以及部分神煞的"得令/失令"分支，
需在裁定后逐条过一遍。

**当前处置（裁定前）**：`DG-JIANCHU-001` 这类**不落标**，保持 `verdict_type: None`
（即 `unspecified`），并在报告的"未归类"节列出。**不得**为了降低 `unlabeled_count`
先标一个 `vote` 顶上——标错一条会让共识分母从 `3/4` 变 `3/5`，阈值判定可能翻转。

**裁定完成定义**：

1. 选定方案（A/B/C 或新方案），并说明为什么另外两个不选；
2. 若选 A/B，给出 `direction_rule` / `verdict_type_when_hit` 的**最小 DSL 子集**
   （支持哪些算子、与现有 `condition` 的关系、求值顺序）；
3. 若选 B，必须同时给出 `severity` 与 `verdict_type_when_hit` 的**优先级、冲突处置、
   单一真相源**；未给出则 B 视为未完成；
4. 若选 C，给出拆分后的规则 id 命名规则与 RT 向量迁移方案；

   `publishable` 的影响；

## Q-027 四离/四绝是否适用安葬？必需集如何定位？（2026-11-04 新增，同日修订）

**背景**

`PUB-SILI-001` / `PUB-SIJUE-001` 的 `task_kinds: []`（= 全部事项）且 `hard_veto: true`，
包括安葬。规则 notes 自己就在问「是否只忌出行、不忌修造」。

**2026-11-04 四库本核查（两处原文必须分开读）**

**① 卷六·义例四「四離 四絕」**（浙江大学图书馆藏影印 `06056507.cn`，viewer n148–n149）：

> 玉門經曰四離者陰陽分至前一辰也……○李鼎祚曰此日忌出行征伐○曹震圭曰四離者冬至前一日水離夏至前一日火離春分前一日陽體分而木亦離也秋分前一日陰體分而金亦離也故名之曰四離
>
> 玉門經曰四絕者四立前一辰也○李鼎祚曰此日忌出軍遠行○曹震圭曰立春木旺水絕立夏火旺木絕立秋金旺土絕立冬水旺金絕故先一日為絕也

这一段只追溯名义与五行，李鼎祚「忌出行征伐／出軍遠行」是**义例溯源**，不是用事宜忌的完整规则。

**② 卷十·用事宜忌**（四库全书本，维基文库转录
<https://zh.wikisource.org/zh-hans/欽定協紀辨方書_(四庫全書本)/卷10>；影印叶次已录：
ARC-005 = n213（用事宜忌忌列）、ARC-006 = n214（按语），待人类核签）：

> 上朔　四离　四绝　晦日
>
> 止不忌祭祀解除沐浴整容剃头整手足甲补垣塞穴扫舍宇修饰垣墙平治道涂破屋坏垣伐木**馀事皆忌**与徳合赦愿并犹忌

按语：

> 按上朔为阴阳与岁徳俱尽之日四离四绝为二气五行分判之日晦为月尽之日**故诸事不宜**惟祭祀解除等事或以事神而不敢禁或以除旧而不为嫌故遇有所宜之神则不忌……

**「餘事皆忌」「諸事不宜」按字面包含安葬。** 此前「原文只忌出行」的结论是错的：李鼎祚那句是义例，卷十才是铺注用的通则。

**③ 卷十一·用事宜忌**（`06056511.cn`）：安葬（viewer n51）、破土（n50）、
行幸遣使·出行同（n22）的忌列均未列四离四绝。这**不能反证安葬不禁**：卷十是
「诸事不宜」的通则层，卷十一是分事项的神煞忌列层；通则已禁的日子不必在每个事项里重复列名。

**结论**

- 按文本忠实读法，四离四绝是「诸事不宜」日，**安葬落在「餘事皆忌」范围内**；
  两条应留在安葬必需集，按 A 级（原文已定位，卷十影印叶次 ARC-005/ARC-006 已录，
  待人类核签）处理。
- 若师傅要把范围收窄到出行，那是**显式偏离協紀**的师承口径，必须写明依据；
  不能用「原文不支持安葬」来论证。

**待裁定：三选一**

| 方案 | 做法 | 影响 |
|---|---|---|
| A. 收窄到出行 | `task_kinds: [出行]`，移出安葬必需集 | **偏离卷十原文**；需师承依据；原文不支持此收窄 |
| B. 降参考层 | `status` 改 `弃用`/`reference`，不投票、不作证据 | 与卷十「诸事不宜」冲突，需比 A 更强的依据；status 属 HUMAN_ONLY |
| C. 维持安葬（文本忠实） | 保留两条为安葬硬否决，核签卷十影印叶次后签名 | 与卷十一致；安葬必需集为 4 条（2026-11-04 实算，见 Q-028） |

**建议 C（文本忠实）**。原方案 A 的 patch 已撤回：其前提「原文只忌出行」不成立。
文件保留在 `docs/patches/0001-sili-sijue-scope.patch.withdrawn`，**不得应用**；
若师傅以师承口径选 A，再按新依据重做。

1. 选定 A/B/C 并说明依据；
2. 若选 C：核签卷十影印叶次（ARC-005 n213 / ARC-006 n214）与逐字 quote → 两条按 A 级

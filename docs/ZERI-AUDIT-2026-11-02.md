# 择日引擎审计报告（2026-11-02）

审计对象：`src/core/zeri/`（事实层、大煞前置层、五派规则包、仲裁层）+ `src/core/engines/zeri.ts`（编排）。
审计方法：逐派读代码对照规格 → 外部核实关键起例 → 表结构与边界自检 → 修复 → 回归。

---

## 一、结论先行

**不能称「全面验证」。** 现有验证是分层的，强弱差别很大：

| 层/派 | 验证手段 | 强度 | 能否发现「口径错」 |
|---|---|---|---|
| 历法事实层 | lunar-javascript + 节气/真太阳时自实现 | 中 | 部分（依赖该库口径） |
| 大煞层（协纪神煞） | 与 cnlunar 2020–2035 共 5844 天逐日对拍 | **强** | 能（42 项神煞与建除值全一致） |
| 三煞 | 自建 37 项用例 + 四层起法对照 | 中 | 能（起法用对照数据钉住） |
| 八宅 | 与独立 MIT 实现 oracle 对拍 | 强 | 能 |
| 玄空飞星 | 与独立 MIT 实现 oracle 对拍（216 局） | 强 | 能 |
| 天星（太阳） | 与 Swiss Ephemeris 对拍，最大偏差 0.014° | 强（仅太阳） | 能（精度） |
| 正五行 | **仅自建用例** | 弱 | **不能** |
| 三合 | 仅自建用例 + 表结构自检 | 弱 | 部分 |
| 董公九星 | 仅自建用例 + 口诀核实 | 中 | 部分 |
| 玄空大卦 | 仅自建用例 + 元运区间自检 | 弱 | **不能** |

**结论**：大煞层与排盘三派（八宅/飞星/玄空盘）有独立实现对拍，可信度较高；
**五派中的正五行、三合、玄空大卦缺少外部 oracle**，目前只能保证「实现自洽」，
不能保证「符合某一派的公认算法」。这不是可以靠写更多测试解决的问题——
需要人类考证者给出该派的权威算例。

## 二、本轮发现并修复的缺陷

### 1. 玄空大卦：跨 0° 的卦覆盖区间为空（严重）

`hexagramsCovering()` 先对角度做 `normalizeDeg`，再比较 `start <= end`。
坐山在 0° 附近时（如 2°），`value - 7.5 = -5.5` 被折成 `354.5`，
得到 `start = 63`、`end = 1`，循环不执行、返回空数组。

**后果**：正北方位（子/癸/壬山一带）的「旺气到山」永远判为「未到」，
`XK_WANG_QI_DAO_SHAN_XIANG` 的 `scoreDelta` 恒为 0。

实测：`covering(0)`、`(2)`、`(5)`、`(355)`、`(358)`、`(359.9)` 全部返回 `[]`。

**修复**：去掉对 `start`/`end` 的二次归一，直接用可能为负的商取整，再由取模回绕。

### 2. 正五行补龙：半合被当成完整三合局（严重）

`sanHeFrame()` 在 `hitCount >= 2` 时就返回一个局，调用方按 `element` 给
旺局 `+2` / 相局 `+1` / 克局 `-2`。而规格明确「缺一为待」。

**后果**：日课只有两支（半合）就拿到满额分，且返回哪个局由 `SAN_HE_FRAMES` 的表顺序决定。

**修复**：改为 `sanHeFrames()` 返回全部命中的局（含 `complete` 标记，完整局优先排序）；
补龙只在 `complete` 时评旺相克，半合给「半合待成」0 分，不足两支给「不成局」。

### 3. 正五行通关：判定过宽

原逻辑「四柱八字里同时出现某两五行」即判相战。四柱八字几乎必然同时含金木水火土，
导致「相战无通关」频繁命中并扣分。

**修复**：按「两五行各见两次以上（成势）」计，单字偶见不算相战，并在理由里写明口径。

### 4. 董公九星：注释与实现矛盾

`THREE_LUCKY_STARS` 的注释写「四吉星：煞贡、直星、人专 + 立早」，
但实现把立早归入六凶星。外部核实（金符经总诀）：「立早妖星惑星共，禾刀四曜有灾刑」——
**立早属凶星，实现正确、注释错误**。已更正注释并补诀文。

### 5. 金神七煞：口径分歧未写明

本表按「天金神 + 地金神」合并，甲己年因此含申酉；
而部分通书只取「甲己年午未」。原 `reason` 只写「官书按语存疑」，未说明这处分歧。
**修复**：在 `reason` 里写明合并口径与差异。

### 6. 正五行：简化口径未标注

- 扶山只按四柱**天干**与坐山五行的生克判，未计地支藏干与纳音；
- 调候只判寒暖燥湿，未实现规格要求的「调候与扶抑冲突时以扶抑为主」。

**修复**：两处理由里显式写明简化范围（`needsHumanReview` 原本已为 true）。

## 三、外部核实结果

| 项 | 核实结论 | 来源强度 |
|---|---|---|
| 金符经九星顺序与起法 | 顺序「妖星、惑星、禾刀、煞贡、直星、卜木、角己、人专、立早」；四孟月甲子起妖星、四仲起惑星、四季起禾刀。**与实现一致** | 多源一致（口诀+文库） |
| 三吉星 | 煞贡、直星、人专；立早属凶 | 同上 |
| 金神七煞 | **至少三个版本**：①甲己午未、乙庚辰巳、丙辛子丑寅卯、丁壬寅卯戌亥、戊癸申酉；②按年干+月支+日支；③丙辛含午未、戊癸含子丑。实现采用「天+地合并」，与 ①③ 部分吻合、对甲己年多出申酉 | 二手来源互相矛盾，**需人工裁定** |
| 玄空大卦卦运 | 「卦气」取外卦洛书数；「卦运」另有父母卦/爻变定运等求法。**实现把两者取同值**（`TRIGRAMS.yun === guaShu`） | 二手来源，**需人工裁定** |
| 玄空大卦元运年数 | 18/24/24/24/21/21/21/27 = 180 年，与阳爻 9 / 阴爻 6 相加一致 | 与规格自洽 |
| 开禧宿度 | 二十八宿古度合计 365.25，折今度 360°，**与实现一致** | 表结构自检 |
| 岁差 | 50.29″/年 与「72 年 1 度」两口径差约 1%，实现两者都提供 | 常识+自检 |

## 四、仍未解决（需人类裁定，不应由 Agent 猜）

1. **玄空大卦卦运求法**：本实现用「内外卦相错取洛书数」，与父母卦体系可能不同。
   已在 `TRIGRAMS`、`guaYun()`、规则包 `conflictFlags` 三处标注。
2. **金神七煞表**：三个流传版本不一致，尤其甲己年是否含申酉。
   当前默认硬排除（可开关），已标 `needsHumanReview`。
3. **正五行扶抑用神**：规格要求「调候与扶抑冲突时以扶抑为主」，尚未实现。
4. **天星宿—山映射**：「巽起角宿等分式」与「依开禧宿度不等宽推定」两法不可同时成立，
   已在 `conflictFlags` 声明，当前采用前者。
5. **五派缺外部 oracle**：正五行、三合、玄空大卦没有权威算例集，
   现有测试只能保证实现自洽。

## 六、给产品的一句话

择日模块现在是「可审计」的：每一处不确定都有标注，每一处简化都有说明。
但它还不是「可验证」的——真正的验证需要各派的权威算例，
这件事只能由人来做，代码能做的只是把「哪里不确定」摆到明面上。
